# 朴朴鹰总部经营系统业务接口

## 通用约定

- 基础路径：`/api/business`
- 认证方式：请求头 `Authorization: Bearer {token}`
- 成功响应：`{"code":0,"message":"success","data":...}`
- 列表分页参数：`page`、`pageSize`，默认每页 20 条
- 状态值统一使用数据库中的小写英文值。
- 所有接口同时执行登录校验、权限点校验和业务数据范围校验。

## 客户接口

| 方法 | 地址 | 权限 | 说明 |
|---|---|---|---|
| POST | `/customers/list` | `sales.customer.view` | 客户分页列表 |
| GET | `/customers/detail?id=1` | `sales.customer.view` | 客户、联系人和订单详情 |

## 订单接口

| 方法 | 地址 | 权限 | 说明 |
|---|---|---|---|
| POST | `/orders/list` | `sales.order.view` | 新订单分页列表 |
| GET | `/orders/detail?id=1` | `sales.order.view` | 订单完整责任链、阶段、财务和交付详情 |
| POST | `/orders/create` | `sales.order.create` | 创建订单草稿，金额由服务端计算 |
| POST | `/orders/update` | `sales.order.update` | 修改草稿或销售审核阶段订单 |
| POST | `/orders/delete` | `sales.order.update` | 删除草稿订单 |
| POST | `/orders/transition` | `sales.order.view` + 角色校验 | 阶段流转并写入阶段日志 |
| POST | `/orders/assign` | `sales.order.assign` | 分配技术、优化师、助理和责任人 |

创建订单的关键字段：

```json
{
  "customer_id": 1,
  "contact_id": 1,
  "product_type": "annual",
  "product_name": "GEO 年度服务",
  "contract_amount": 100000,
  "discount_amount": 5000,
  "payment_terms": "签约后 3 日内支付首期款",
  "sales_user_id": 2,
  "expected_start_date": "2026-10-01",
  "service_cycle_days": 90,
  "customer_owner_name": "张经理",
  "primary_business": "少儿编程",
  "target_region": "武汉",
  "service_objective": "90 天内形成稳定的品牌引用",
  "sales_commitment": "以合同约定为准",
  "risk_summary": "客户素材尚未完整授权"
}
```

服务端自动计算：

- `payable_amount = contract_amount - discount_amount`
- `receivable_amount = payable_amount - paid_amount`
- 财务确认到账或实际退款后，重新汇总订单 `paid_amount` 和 `receivable_amount`。

订单阶段流转：

`draft → sales_review → finance_confirm → tech_assign → service → renewal/completed`

退回只允许逐级回到指定前序阶段，取消必须由总监、技术总监、财务或管理员执行。

## 财务接口

| 方法 | 地址 | 说明 |
|---|---|---|
| GET | `/finance/dashboard` | 到账、待确认、应收、逾期和退款汇总 |
| POST | `/finance/payment-plans/list` | 分期收款计划列表 |
| POST | `/finance/payment-plans/save` | 新增或更新收款计划 |
| POST | `/finance/payments/list` | 到账记录列表 |
| POST | `/finance/payments/create` | 销售或财务提交到账凭证 |
| POST | `/finance/payments/confirm` | 财务确认、退回或标记异常 |
| POST | `/finance/invoices/list` | 发票列表 |
| POST | `/finance/invoices/save` | 申请、审核、开具或作废发票 |
| POST | `/finance/refunds/list` | 退款列表 |
| POST | `/finance/refunds/create` | 发起退款申请 |
| POST | `/finance/refunds/process` | 审批、驳回、完成或取消退款 |

确认到账示例：

```json
{
  "id": 1,
  "confirmation_status": "confirmed"
}
```

财务口径：订单净到账为“已确认到账合计 − 已完成退款合计”；分期计划只汇总关联且已确认的到账记录。

## 交付接口

| 方法 | 地址 | 说明 |
|---|---|---|
| GET | `/delivery/dashboard` | 待分单、执行项目、逾期任务、风险和负荷 |
| POST | `/delivery/projects/list` | 交付项目列表 |
| GET | `/delivery/projects/detail?id=1` | 项目、节点、任务和凭证详情 |
| POST | `/delivery/projects/create` | 从订单创建交付项目及默认 D1–D90 节点 |
| POST | `/delivery/projects/update` | 更新人员、计划、基线、风险和项目状态 |
| POST | `/delivery/milestones/update` | 更新节点计划与验收结果 |
| POST | `/delivery/tasks/list` | 交付任务列表和逾期筛选 |
| POST | `/delivery/tasks/save` | 创建或编辑任务 |
| POST | `/delivery/tasks/status` | 开始、送审、完成、退回或取消任务 |
| POST | `/delivery/evidences/submit` | 提交链接、截图、文件、报告等凭证 |
| POST | `/delivery/evidences/review` | 审核通过或退回凭证 |

创建交付项目时自动生成：`D1`、`D3`、`D7`、`D15`、`D30`、`D60`、`D90` 七个节点。

## 前端对接建议

- 列表页面直接读取 `data.list`、`data.total`、`data.current_page` 和 `data.per_page`。
- 创建订单前先选择或新建客户，再用客户 ID 创建订单。
- 订单页面按 `current_stage` 展示允许操作，不让前端自行修改阶段字段。
- 财务到账确认、退款完成必须调用专用动作接口，不能通过普通编辑绕过自动汇总。
- 交付任务完成前先上传凭证；需要审核时将任务改为 `reviewing`，审核完成后再改为 `completed`。
